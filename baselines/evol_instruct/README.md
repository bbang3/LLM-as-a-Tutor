# Evol-Instruct Baseline

Offline pipeline that produces a static, evolved version of the
wildchecklists training set for use as an RL baseline. The goal is to
isolate the contribution of **RM-based prompt selection** in EVA from the
contribution of **prompt evolution itself**.

| Method | Selection signal | Evolution mechanism |
|---|---|---|
| Ours (constraint / adaptive / refine) | Response-grounded (judge sees rollouts) | Targeted edit |
| EVA (Ye et al. 2024) | Reward-grounded (max−min over rollouts) | Evol-Instruct rewrite |
| **Evol-Instruct (this baseline)** | **Random** (every prompt evolved 1-to-1) | **Evol-Instruct rewrite** |
| SFT distillation | n/a (no selection — distill teacher response) | n/a |

If Evol-Instruct ≪ EVA, the gain comes from RM-based selection. If
Evol-Instruct ≈ EVA, the gain comes from prompt-distribution evolution
that random selection can also achieve.

---

## Mechanism

Faithful to **WizardLM/Evol-Instruct (Xu et al. 2023)** with no EVA-style
80/20 pool mix. Each prompt is taken through `M=4` sequential evolution
rounds and the **last successful evolution** replaces the original 1-to-1.
The final dataset has the same row count as the input (minus an overlong
filter applied beforehand).

Per-round, per-prompt:
1. Sample one of 5 distilabel mutation methods uniformly:
   - **Add Constraints** (in-depth, `#Rewritten Prompt#:` marker)
   - **Deepening** (in-depth)
   - **Concretizing** (in-depth)
   - **Increased Reasoning Steps** (in-depth)
   - **Breadth** (in-breadth, `#Created Prompt#:` marker)
2. Render the chosen template with the row's *current* chain state.
3. Generate one candidate (Pass 1, `n=1`) via Qwen3-8B chat completion.
4. If parsing / length / change validation fails, oversample five
   candidates with the same template (Pass 2, `n=5`) and take the first
   valid one.
5. If all six attempts fail, the chain stays at its previous depth and
   the next round retries with a freshly sampled method.

After the chain finishes, rows with `depth >= 1` get their general rubric
regenerated by the same Qwen3-8B judge using the standard
`data_generation/prompts/base_rubric_generation.txt` template (same 2-pass
retry). Rows where rubric regen still fails revert to the original prompt
+ original rubric, so every saved row has a prompt-aligned rubric.

### What's faithful, what diverges

**Faithful to Evol-Instruct paper:**
- 1-to-1 chain replacement with `M=4` rounds.
- 5-method uniform sampling per round (Complicate Input is dropped,
  matching distilabel's omission — the 4 in-depth + 1 in-breadth set).
- Standard WizardLM prompt prefix and method-specific instructions.

**Aligned with the EVA baseline:**
- Mutation-template files in `prompts/` are byte-identical to the
  templates the EVA pipeline uses
  (`data_generation/prompts/evol_instruct/*.txt`). They diverge slightly
  from raw distilabel (single-newline line breaks vs `\n\n`, no
  `'#The Given Prompt#'` quote wrapping in `add_constraints`, trailing
  period after `...Rewritten Prompt#`). Functional impact is negligible
  and using the same templates makes selection mechanism the only
  operational difference between the two baselines.

**Diverges from distilabel default:**
- Strict marker parsing → **lenient** marker parsing. Qwen3-8B almost
  never emits the canonical `#Rewritten Prompt#:` prefix (raw analysis
  on full run: 95/95 in-depth and 33/33 breadth outputs had no marker).
  The parser tolerates colon-less, markdown-bolded, and prefix-absent
  outputs, and falls back to "the entire post-`<think>` text is the
  rewrite" when no marker is found at all. Without this, every Pass-1
  attempt would parse-fail.

**Operational difference vs EVA:**
- No scalar-RM scoring step (EVA's Step 1.5).
- No info computation (`max−min` reward gap).
- No top-K weighted sampling (EVA's Step 1.7) — every prompt is evolved.
- No 80/20 pool mix (EVA's Step 1.10) — chain output replaces original
  1-to-1.

## Hyperparameters

| Parameter | Value | Source |
|---|---|---|
| Evolving LLM | Qwen3-8B (same as RL judge) | Match all other baselines |
| Sampling | `temp=0.6, top_p=0.95, top_k=20` | RL `data_generator` defaults |
| `max_tokens` | 4096 | RL `data.max_response_length` |
| `max_model_len` | 20480 (8k prompt + 12k think+answer headroom) | Generous to avoid truncation |
| `max_prompt_length` | 8192 | RL `data.max_prompt_length` filter |
| Turns `M` | 4 | Evol-Instruct paper default |
| Pass-2 oversample `n` | 5 | Empirical — most failures rescued in 1 retry |
| `enable_thinking` | true | Match RL judge calls |
| Tokenization for length guard | Chat-templated, with `enable_thinking` | Matches RL training-time tokenization |

The seed is unfixed (per-process `np.random.default_rng()`), matching
the EVA pipeline.

The companion RL config lives at
`configs/evol_instruct_baseline.yaml`. It inherits
`llm_tutor_base` and disables `AdaptiveDataset` so the trainer's
`OnlineDataGenerator` is never instantiated — the static evolved
prompt + regenerated rubric pass through unchanged across all training
epochs. Reward function reads `requirements_general` / `weights_general`
via the same `keep_keys` pattern used by `llm_tutor_base_rubrics`.

## Usage

### Generate the dataset

```bash
# Full run on 4k prompts with TP=2 (Qwen3-8B fits on a single H100/B200,
# but TP=2 doubles throughput for the batched chain rounds).
TS=$(date +%Y%m%d_%H%M%S)
LOG="baselines/evol_instruct/logs/evol_full_${TS}.log"
RAW="baselines/evol_instruct/logs/evol_full_${TS}_raw.jsonl"
REPORT="baselines/evol_instruct/logs/evol_full_${TS}_report.jsonl"
CUDA_VISIBLE_DEVICES=4,5 nohup .venv/bin/python -u \
    baselines/evol_instruct/evol_instruct_offline.py \
    --output ./datasets/evol_instruct_baseline/wildchecklists_evolved.parquet \
    --tensor-parallel-size 2 \
    --raw-jsonl "${RAW}" \
    --report-jsonl "${REPORT}" \
    > "${LOG}" 2>&1 &
```

Smoke test on 32 prompts, single GPU:
```bash
CUDA_VISIBLE_DEVICES=3 .venv/bin/python -u \
    baselines/evol_instruct/evol_instruct_offline.py \
    --output /tmp/evol_smoke.parquet \
    --tensor-parallel-size 1 \
    --max-samples 32 \
    --raw-jsonl /tmp/evol_smoke_raw.jsonl
```

### RL training

The dataset is published at `BBang3/wildchecklists-evol-instruct` (public
HF dataset, same overlong filter as the RL run, 3994 rows). Launch the
RL config the same way as any other LLM-as-a-Tutor variant:

```bash
bash run_train.sh configs evol_instruct_baseline
```

## Output schema

Saved to parquet (and pushed to `BBang3/wildchecklists-evol-instruct`):

| Column | Type | Notes |
|---|---|---|
| `prompt` | `list[{role, content}]` | Evolved prompt as a single-turn user message (or original if `evol_depth == 0`) |
| `requirements_general` | `list[str]` | Rubric criteria, regenerated for evolved rows |
| `weights_general` | `list[float]` | Importance scores 0–100 |
| `data_source` | `str` | Carried through from `wildchecklists-with-general` |
| `evol_depth` | `int` | Round number of last successful evolution (0..M) |
| `evol_methods` | `list[str]` | Methods that successfully advanced the chain, in order. **Note**: this is the actual chain depth — `len(evol_methods)` may be less than `evol_depth` when an intermediate round failed. |
| `evol_was_evolved` | `bool` | `evol_depth >= 1` AND rubric regen succeeded |
| `rubric_regen_failed` | `bool` | True only if depth was ≥1 but rubric regen failed; that row reverted to original |
| `original_prompt` | `str` | Raw user-content of the original `wildchecklists-with-general` prompt; included so downstream analysis can quantify how far prompts drifted |

## Known limitations

- **Length explosion at higher depths.** Breadth + deepen tend to balloon
  outputs; the worst single row reaches 17k chars after 4 rounds. The
  length guard rejects evolved prompts above 8192 tokens (chat-templated)
  but doesn't constrain shorter-but-still-long results. p99 stays under
  4327 chars, well within budget.
- **No semantic dedup.** Evol-Instruct can converge two originally
  distinct prompts onto similar evolved forms (especially via in-breadth).
  We don't filter; the random selection assumption tolerates this.
- **Marker parsing is permissive.** When the model produces an unrelated
  preamble (e.g., "Here's a more complex version: ..."), the lenient
  parser accepts the entire post-`<think>` text. In practice this is
  rare for Qwen3-8B (most outputs are clean rewrites), but it's the
  right place to look first if downstream training shows quality drops.
- **`evol_depth` field semantics.** `evol_depth` is the round number of
  the *last* successful evolution, not the count of successful
  evolutions. For 99.8% of rows these are equal (all 4 rounds succeed),
  but the 8 depth-3 rows skipped one intermediate round. Use
  `len(evol_methods)` if you need the actual chain length.
